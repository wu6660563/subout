# TUN 连接审计设计

## 目标

为 Subout 管理的 sing-box TUN 流量提供低噪声的连接审计视图，回答以下问题：

- 哪个进程访问了哪个原始目标（域名或 IP）？
- 哪些请求走了 `PROXY`，以及通过了哪个节点？
- 走代理时最终使用了哪个节点，以及完整出站组链路是什么？

本功能仅支持 TUN，不支持系统代理模式的端口/PID 反向关联。

## 数据来源与前置条件

1. 生成运行配置时启用 `route.find_process: true`，由 sing-box 为 TUN 连接查找进程。
2. 解析由 Subout 捕获的 sing-box stdout、stderr 与可选文件输出，关联同一连接的入站、路由和出站信息。
3. 启用 sing-box 本地 Clash RESTful API（配置编辑器“实验性 / Clash RESTful API 接口（`clash_api`）”），使用其运行时状态展开 selector、urltest 与嵌套出站组。
4. 使用 sing-box 原始连接日志中的连接 ID 进行事件拼接，避免用时间邻近猜测连接关系。

审计功能启用时由 Subout 自动管理该 API：运行配置中的 `external_controller` 固定为 `127.0.0.1:<本地端口>`，使用随机 secret。浏览器不直接接触 API 或 secret；Subout 后端持有 secret 并代理所需的只读状态。接口绝不监听局域网地址，也不访问互联网。

如果用户在专家配置中手动禁用 `clash_api`，审计仍记录已解析的代理路由，但无法可靠展开最终节点；页面必须显示对应的降级状态。

## 目标展示规则

主列表忠实显示应用的原始请求目标：

- 有可靠域名来源时：`www.youtube.com:443`。
- 请求原本为 IP 或没有可靠域名来源时：`142.250.x.x:443`。
- 不执行反向 DNS，也不根据公共 DNS 推测域名。

TUN 中多数连接最终以 IP 报文进入。域名只可来自连接自身可识别的域名（例如 TLS SNI / HTTP Host），或同一进程此前的 DNS 查询与解析结果的可靠关联。DNS 关联限制在 `进程 + IP` 和五分钟窗口内；多个候选域名时主列表显示 IP，详情列出候选项并标记为歧义。DNS 事件默认不单独进入审计列表，仅用于补全连接；排障时可开启 DNS 事件显示。

## 路由与节点展开

每个审计事件保存路由快照：

```text
PROXY: 代理 -> 香港自动 -> HK-02
```

主列表的节点列显示订阅名称与最终节点（例：`飞鸟云/HK-02`）；详情显示完整出站链路。节点标签在数据库中唯一对应订阅名称时附加此前缀；标签冲突或未知时仅显示节点名，避免错误归属。直连请求不写入审计。对于 selector 和 urltest，收到连接路由事件时立刻读取 Clash API 的当前状态，并递归展开嵌套组。该快照代表连接创建时的实际选择，之后切换节点不会篡改旧事件。

若运行时 API 不可用或组无法完全展开，仍记录连接，节点列显示“节点未知”，详情保留已知出站组和解析错误。

## 命中的路由规则

审计事件在可从 sing-box 路由日志可靠取得时，同时保存命中的规则信息，避免只看到出站节点却无法解释“为什么这样走”：

- 规则序号或稳定标识（例如 `#3`）；
- 规则 tag（配置中存在时）；
- 规则摘要（例如域名、端口、进程等匹配条件）；
- 规则动作（例如 `route`、`reject` 或对应出站组）；
- 关联的原始 sing-box 路由日志行，便于排障。

主列表可显示简短规则标识，完整规则信息放在展开详情中，避免表格过宽。规则信息必须来自实际运行日志或运行时状态；如果 sing-box 没有输出可关联的规则，显示“规则未知”，不根据静态配置或出站结果反向推断。规则字段发生变化时纳入事件指纹并新增变更记录。

## 去重与变更

当前状态唯一键为：

```text
PID + 进程路径 + 原始目标（域名或 IP）+ 目标端口 + 网络协议（TCP/UDP）
```

同一个键的重复连接不新增记录，只更新最后观察时间。以下情况新增一条变更事件：

- 首次观察到连接；
- 最终节点变化；
- 完整出站组链路变化；
- 进程实例或可执行路径变化；
- 原先只有 IP 的记录获得唯一、可靠的域名补全。

进程展示为名称、PID 和完整路径；去重使用路径以避免同名程序合并。PID 退出后相应当前状态会被回收，避免 PID 重用造成串记录。

每行还保存命中次数：重复命中同一键与同一路由快照时次数递增。连接 ID 显示最近一次命中的 sing-box 连接 ID；它不是该聚合记录的首个连接 ID。

## 保留策略与交互

- 审计事件仅使用内存环形缓冲，不落盘；Subout 或 sing-box 重启时清空。
- 页面提供“审计保留时长”设置，固定选项为 10、20 分钟；默认 20 分钟，最大 20 分钟。
- 用户选择的保留时长和“记录连接审计日志”开关写入现有 SQLite 设置表并在启动时恢复；访问目标、进程和审计事件不写入 SQLite。
- “记录连接审计日志”默认开启。关闭时立即清空内存中的审计事件与当前画像，并停止后续解析/记录；重新开启后仅记录新的 TUN 连接，不能恢复已清空的记录。
- 设置变更立即生效：缩短时立刻清理超出新窗口的事件，延长时只影响之后尚未过期的内存事件，无法恢复此前已清理的数据。
- 每分钟清理超过当前保留窗口的事件。
- 内存最多保留 20,000 条变更事件；达到上限时淘汰最旧事件。
- 进程/规则关联上下文最多保留 20,000 条，且 5 分钟未更新即淘汰；普通连接行不会创建空上下文。
- 当前画像只包含窗口内的状态。
- 仅记录 `PROXY`；直连事件在采集端丢弃，不进入内存审计数据。
- 提供按进程（名称、PID、路径）和原始域名/IP 的不区分大小写检索；可叠加节点、协议和时间筛选。
- 页面操作区提供：
  - “记录连接审计日志”开关；
  - 进程关键字与域名/IP 关键字检索；
  - 节点、TCP/UDP 和时间范围过滤；
  - “刷新”按钮，立即拉取最新内存快照；
  - 默认开启的实时刷新开关（可关闭，关闭后仅手动刷新）；
  - “清空日志”按钮，二次确认后清空当前内存审计事件与当前画像。
- 清空日志不影响 SQLite 中持久化的审计保留时长和记录开关偏好，同时重置本次运行的异步队列丢弃计数。

## 页面形态

新增独立的“连接审计”页面，而不是混入原始核心日志。每行包含：

```text
时间 | 进程（名称 / PID） | 目标（域名或 IP:端口） | TCP/UDP | PROXY | 最终节点
```

展开详情展示进程路径、首次/最后观察时间、解析 IP、域名来源与置信状态、命中的路由规则（序号、tag、摘要、动作）、完整出站链路、sing-box 连接 ID、以及关联的原始日志行。原始日志默认折叠，仅用于排障。

### 状态、排序与操作

- 顶部状态区分别展示“进程识别”“sing-box 日志解析”“节点展开”的健康状态；节点 API 不可用时明确提示“仍可记录路由，节点未知”。
- 支持按首次时间、最后观察时间、进程和节点排序。
- 用户滚动查看旧记录时不强制跳转到底部；有新事件时显示“有 N 条新记录”提示，用户点击后才跳转。
- 详情支持复制单条完整审计信息和复制当前已过滤结果。
- 实时刷新默认 1 至 2 秒。页面隐藏或用户关闭实时刷新时暂停轮询。
- 页面显示当前事件数、选定保留时长、最早事件距过期的大致时间；内存上限触发淘汰或异步审计队列丢弃原始日志时显示提示。

## 异常与性能

- 日志格式无法解析时保留为原始核心日志，不生成不可靠审计事件。
- 找不到进程信息时可显示“未知进程”，但不与已识别进程合并。
- API/日志解析失败只降级节点或详情字段，不丢失已确认的路由事件。异步队列饱和时会丢弃新到达的原始日志，并将累计数量返回页面，避免阻塞核心日志读取。
- stdout、stderr 与 sing-box 文件日志可能重复输出同一原始行；审计 worker 在 1 秒窗口内去重，避免虚增命中次数。
- 对长连接与 UDP/QUIC 仅记录首次观察及状态变化，绝不按数据包或心跳刷屏。

## 实现与验证备注

- 当前实现已通过 Rust 全量测试、前端全量测试、类型检查和生产构建。
- `cargo clippy --lib --all-features` 可通过，但严格的 `cargo clippy --all-targets --all-features -- -D warnings` 仍会被仓库原有的 9 条警告阻断，涉及 `db`、`generator`、`platform` 和 `web/nodes`，不属于连接审计改动；后续可单独清理。
- 需要实际 TUN、管理员权限和可运行的 sing-box 内核才能完成真实流量联调；未具备这些外部条件时，保留单元/组件测试作为验证依据，不在代码中伪造运行结果。
- 审查待办：专家配置编辑器在关闭 `clash_api` 时会移除该配置；运行时目前无法区分“用户明确关闭”与“未配置、允许 Subout 自动管理”，因此会重新注入本地 API。后续应引入单独的持久化意图标记，再实现“关闭 API 但仍记录路由、节点未知”的精确降级语义。当前可使用“记录连接审计日志”开关完全停止审计记录。
- 审查待办：为降低 `/proxies` 查询压力，当前使用短 TTL 缓存；selector/urltest 若在缓存窗口内切换，可能短暂显示旧节点。后续应分离静态拓扑缓存与动态组当前选择读取，在不牺牲连接节点准确性的前提下优化性能。
